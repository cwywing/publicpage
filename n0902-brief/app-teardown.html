商店一句话：Turn regular mobile into eSIM-ready devices via Beesim Bluetooth eSIM card。

公开页卖点：BLE 管 eUICC 的写入、启用、停用、删除；插卡后搜「BeeSIM」前缀；扫码解析 DP+ 与激活码；启用后卡会重启并断连重连。

公开接口样例

2026-09-15 对公开路径做的产品探测。只记版本检查和购买渠道。后台登录、口令、未鉴权利用一律不写。

API_BASE_URL = "http://www.liankemobile.com/prod-api"
API_PATHS = {
  checkVersion:      "/app/version/check",
  purchaseChannels:  "/app/purchaseChannel/list",
  diagnosticLog:     "/app/diagnostic/log/report"
}
# 另有历史路径也可通：/foxisim/app/version/check
# 包内开发残留（勿当正式依赖）：内网地址、临时反代域名

BeeSIM · simhub

HTTPS 主机：https://api.simhub.cn
1) /v2/plugin/esim/rsp/es9plus/execute   — RSP / ES9+ 执行入口命名
2) /v2/plugin/mall/firmware.do           — 固件商城 / 升级检查

无业务 body 的裸 GET（2026-09-15）只说明主机存活：
{"status":500,"msg":"服务器异常，请稍后再试！","i18n":"res.server.error"}

Bee 写卡主路径仍是本地 BLE。云接口需要业务 body。官网 H5 历史脚手架还写过 baseURL: https://www.beeesim.com/，别当成飞狐现网后端。

两边用户路径高度同构：插卡 → 开蓝牙（安卓还要定位）→ 扫卡绑定 → 扫码或输入 LPA:1$smdp$matchingId → 下载并启用（可能重启 / 断连）→ 列表管理，可选固件升级。差异在套餐商业化和是否锁死官方 App。

Bee Android

RN + Hermes，单页。BLE 在 JS 层（scan / notify / write / reconnect 文案都在）。云：simhub ES9+ 和固件。

飞狐 Android

uni-app 壳 + 两个原生 module。FoxiSimSDK 收敛 BLE / OMA / LPA。云只做版本、统计、购买导流。写卡主路径本地。

对我们

不要用 uni-app / RN 壳去包 LPA。GATT / ES10x / 命令队列必须原生，并预留 ARA-M 绑我们自己的 Team ID 和包签名。

自建 App 清单

信息架构（偏飞狐）

  • Tab1 卡管理：连接状态、EID、一键连接 / 连接管理、空态指南
  • Tab2 套餐：列表、空间占用、启用 / 禁用 / 删除、改名、扫码 / 粘贴
  • Tab3 更多：固件升级、语言、帮助、隐私、关于、可选购买导流

必做体验

  • 权限引导：蓝牙 +（Android）定位，失败可重试
  • 断线自动重连，重连后刷新 Profile 列表
  • 写卡 / 启用：禁退出、进度、卡重启预期说明
  • 删除 Profile 二次确认
  • 固件升级独立页 + 「勿退出」
  • 演示模式（无卡走完主路径，方便销售和审核）
  • Profile 自定义名称；槽位按剩余 eUICC 空间，不写死 N 条

差异化（偏 Bee + 我们现有生意）

  • 多通道：官方 App +（可选）Web BLE + 兼容开源 LPA（前提是 GATT 文档化）
  • 套餐购买留在现有 DTC / Amazon / 激活码流。App 内只导流或深链
  • 商店合规段对标飞狐：不碰系统 eSIM、不卖未授权码、只管理自有硬件

工程验收（对齐见面 brief 的 go / no-go）

卡在 iPhone 上能被 nRF Connect 扫到。用我们真实 LPA:1$…$… 写入并可驻网，不依赖对方云、无 per-download 锁。Consumer SGP.22 + SAS-UP。SDK 是 iOS XCFramework / Android AAR，绑定我们 Team ID 与包签名。

未做动态调试，未还原完整私有 GATT，未抓实时 ES9+ / ES10x 报文。未登录任何后台。社区硬件对照见 见面 brief。
